# 历史增量索引验收记录

本文记录历史读取优化的实现边界和验证方式。真实用量、线程内容、来源路径和本机诊断记录仅保存在 Git 忽略的本地目录，不随源码发布。

## 读取与发布

- 首页摘要、官方额度和任务读取分别调度；完整历史在后台处理。
- SQLite 派生索引以检查点续读，支持追加、改写、父子线程公共前缀去重和 Claude 消息去重。
- 只允许完整归档替换完整累计、明细和领导力；部分结果或失败继续保留上次完整值，并显示实际读取状态。
- 数据库及旁文件使用私有权限和单写者锁；原始日志不在清理范围内。
- 索引空间预算为 2 GiB，主数据库上限为 1792 MiB。过期未发布的报告按最多 256 行分批回收，保留当前发布结果和使用中的版本；回收页面供后续写入复用。
- 可执行程序定位兼容 ChatGPT/Codex 新旧内嵌 CLI、改名或移动的应用及常规 CLI 软链。

## 回归覆盖

`scripts/test-history-index.sh` 包括计数器、SQLite 事务/锁/权限、流式解析、追加与原子替换、清单覆盖、检查点恢复、跨时区归档、父子去重、Claude 所有权、推理与领导力聚合、大记录投影及首页缓存回归。报告回收测试覆盖超过批次上限的数据、后续取消不回滚此前进度、已发布和使用中版本保留。首页状态测试覆盖故障提示、完整值保留及成功恢复。

发布包装另运行全局内存风险门禁、macOS 兼容检查、额度归一化、app-server 部分读取与 EOF、Claude Skill 根路径、状态栏、粒子生命周期、更新及 parser 检查。

## 探针和性能边界

- `--probe-home` 测量首页模型可用性，不测原生绘制。
- `--probe-history-index` 使用实际后台历史服务，并要求本轮启动后产生的新完整结果；启动前缓存不能证明本轮回填完成。
- 退出应用后可运行 `--maintain-history-index`，对既有索引执行受写锁保护的报告回收。
- 一致性副本和正式索引均已检查事实、来源世代、检查点、已发布结果及使用中版本保留，并通过 SQLite quick_check 和 foreign_key_check。
- 单次本机积压修复后已观察到新完整归档发布，安装与退出重开后额度、统计和领导力正常显示。

上述结果不构成任意数据规模下的五秒原生启动保证，也不替代 Intel、各 macOS 版本或 Windows 的完整原生性能矩阵。具体构建与安装验证见对应版本的发布记录；本机备份及诊断结果不上传。
